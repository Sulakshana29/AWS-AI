Domain 1 of 5
Fundamentals of AI and Machine Learning
Core terminology, ML types, lifecycle, key metrics & foundational AWS services
20%
💡
My Advice: Domain 1 is your foundation. Don't skip it even though it's only 20% — concepts like supervised/unsupervised learning and the ML lifecycle underpin all other domains. Spend ~3-4 hours here solidly before moving on.
📚 Topics to Study
AI vs ML vs Deep Learning vs GenAI — key differences ▼

Artificial Intelligence (AI): Broad field of machines simulating human intelligence (e.g., chess engines).

Machine Learning (ML): Subset of AI where systems learn from data without explicit programming (e.g., spam filters).

Deep Learning (DL): Subset of ML using multi-layered neural networks (e.g., image recognition).

Generative AI: Subset of DL that generates new content (text, images, code) instead of just predicting classes.

Supervised Learning (classification, regression) ▼

Supervised learning involves training a model on labeled data. The model learns to map input features to the correct output label.

  • Classification: Predicting discrete categories (e.g., Is this email Spam or Not Spam?).
  • Regression: Predicting continuous numerical values (e.g., What will be the price of this house?).
Unsupervised Learning (clustering, dimensionality reduction) ▼

Unsupervised learning finds hidden patterns in unlabeled data without prior human guidance.

  • Clustering (e.g., K-Means): Grouping similar data points together (e.g., customer segmentation).
  • Dimensionality Reduction (e.g., PCA): Simplifying data while retaining key information.
  • Anomaly Detection: Finding unusual patterns (e.g., fraud detection).
Reinforcement Learning concepts ▼

An agent learns by interacting with an environment. It performs actions and receives rewards or penalties.

The goal is to maximize cumulative reward over time. Often used in robotics, game playing (like AlphaGo), and optimizing complex systems.

ML Lifecycle: Data → Prepare → Train → Evaluate → Deploy → Monitor ▼
  1. Data Collection: Gathering raw data.
  2. Data Preparation: Cleaning, formatting, and feature engineering.
  3. Model Training: Feeding data into algorithms to learn patterns.
  4. Evaluation: Testing accuracy on unseen data.
  5. Deployment: Making the model available for predictions (inference).
  6. Monitoring: Tracking model performance over time to detect drift.
Neural networks basics (layers, activation functions) ▼

Inspired by the human brain, composed of interconnected nodes (neurons).

  • Input Layer: Receives raw data.
  • Hidden Layers: Perform computations to find patterns. More layers = "Deep" learning.
  • Output Layer: Delivers the final prediction.
  • Activation Functions: Decide whether a neuron should "fire" (e.g., ReLU, Sigmoid), introducing non-linearity.
Overfitting vs Underfitting; Bias-Variance tradeoff ▼
  • Overfitting (High Variance): Model memorizes the training data but performs poorly on new data. Fix: more data, regularization, simpler model.
  • Underfitting (High Bias): Model is too simple to capture the underlying patterns. Fix: more complex model, better features.
Evaluation metrics: Accuracy, Precision, Recall, F1, AUC-ROC ▼
  • Accuracy: Overall correct predictions (bad for imbalanced data).
  • Precision: TP / (TP + FP). Out of all predicted positives, how many were actually positive?
  • Recall: TP / (TP + FN). Out of all actual positives, how many did we find?
  • F1 Score: Harmonic mean of Precision and Recall.
  • AUC-ROC: Measures ability to distinguish between classes.
Feature engineering & data preprocessing ▼

Transforming raw data into formats ML algorithms can understand.

  • Imputation: Handling missing values.
  • Normalization/Scaling: Adjusting numerical values to a standard range.
  • One-Hot Encoding: Converting categorical text (like colors) into binary columns (1s and 0s).
Training vs Validation vs Test splits ▼

Data must be divided to prevent cheating (data leakage) and overfitting.

  • Training Set (70-80%): Used to train the model.
  • Validation Set (10-15%): Used during training to tune hyperparameters and check for overfitting.
  • Test Set (10-15%): Completely unseen data used only once for final evaluation.
Hyperparameter tuning concepts ▼

Parameters are learned automatically by the model (e.g., weights in a neural network).

Hyperparameters are settings configured by humans before training begins (e.g., learning rate, number of layers, batch size). Tuning them optimizes model performance.

Amazon SageMaker overview & Studio ▼

Amazon SageMaker: A fully managed service to build, train, and deploy ML models at scale.

SageMaker Studio: The centralized IDE (Integrated Development Environment) for SageMaker, offering a unified web interface for the entire ML lifecycle.

SageMaker Canvas (no-code ML) ▼

A visual, no-code ML capability designed for business analysts. It allows users to generate accurate ML predictions without writing any code or requiring ML expertise.

SageMaker Ground Truth (data labeling) ▼

A managed service that helps you build highly accurate training datasets. It routes raw data (images, text, video) to human reviewers (via Amazon Mechanical Turk, internal teams, or vendors) to be accurately labeled.

🔑 Key Concepts
Supervised Learning
Model trained on labeled data. Learns mapping from inputs → outputs. Includes classification (discrete) and regression (continuous).
Unsupervised Learning
Finds patterns in unlabeled data. Key techniques: K-Means clustering, PCA for dimensionality reduction, anomaly detection.
Reinforcement Learning
Agent learns by interacting with an environment, receiving rewards/penalties. Used in game-playing AI, robotics, optimization.
Overfitting
Model memorizes training data but fails on new data. Fix: more data, regularization (L1/L2), dropout, simpler model.
Precision vs Recall
Precision = TP/(TP+FP) — of all predicted positives, how many are real. Recall = TP/(TP+FN) — of all actual positives, how many did we catch. F1 balances both.
Confusion Matrix
Table showing TP, TN, FP, FN for classification models. Basis for Precision, Recall, F1, Accuracy calculations.

🔑 Key Concepts
Foundation Model
A large model trained on massive datasets that can be adapted (via fine-tuning or prompting) for many tasks. Examples: Claude, Titan, Llama, Stable Diffusion.
Token
The basic unit of text for LLMs. Roughly 1 token ≈ 0.75 words. LLMs have a context window limit measured in tokens (e.g., 100K tokens).
Embedding
A numerical vector representing text, image, or audio in a high-dimensional space. Similar meanings → similar vectors. Used in RAG and semantic search.
Temperature
Controls output randomness. High temperature (>1) = more creative/random. Low temperature (<0.3) = more deterministic/focused. 0 = greedy decoding.
RLHF
Reinforcement Learning from Human Feedback — technique used to align LLM outputs with human preferences. Humans rate responses, model learns from ratings.
Context Window
Maximum amount of text (tokens) an LLM can process at once. Larger context = more expensive but handles longer documents. Key for RAG applications.

🔑 Key Concepts
RAG
Retrieval-Augmented Generation: retrieve relevant documents from a knowledge base, inject them into the prompt context, then generate grounded answers. Reduces hallucinations.
Bedrock Knowledge Base
Managed RAG service on AWS. Connect your S3 documents, it auto-creates embeddings in a vector store, and provides a query API. No infrastructure to manage.
Bedrock Agents
Autonomous agents that can plan multi-step workflows, call APIs/Lambda functions, and use Knowledge Bases. Think: AI that takes actions, not just responds.
Bedrock Guardrails
Safety layer for Bedrock apps: filter harmful content, block topics, redact PII, detect grounding, and apply watermarks. Applied to both inputs and outputs.
Zero-shot Prompting
Give the model a task with no examples — rely on its pre-trained knowledge. Best when task is simple/straightforward.
Few-shot Prompting
Provide 2-5 examples of input→output pairs in the prompt. Guides model behavior for specific formats or patterns.
Chain-of-Thought
Ask the model to "think step by step" before answering. Dramatically improves accuracy on reasoning and math tasks.
Amazon Q Business
Managed GenAI assistant for enterprises — connects to 40+ data sources (SharePoint, Salesforce, S3) with permission-aware answers. No model expertise needed.

🔑 Key Concepts
Data Bias
Training data that over- or under-represents certain groups leads to unfair model predictions. Example: facial recognition trained mostly on light-skinned faces.
SHAP Values
SHapley Additive exPlanations — a method to explain how much each feature contributed to a specific prediction. Used by SageMaker Clarify.
Human-in-the-Loop
Keeping humans involved in AI decision-making for high-stakes scenarios. AWS A2I (Augmented AI) implements HITL workflows for reviewing model predictions.
Hallucination
When an LLM confidently generates factually incorrect information. Mitigation: RAG (grounding in real documents), Bedrock Guardrails grounding check.
AI Service Cards
AWS documentation that details intended use cases, limitations, and responsible AI considerations for each AWS AI service. Important for transparency.
SageMaker Clarify
AWS tool that detects bias in datasets and models at training time, and provides feature importance (explainability) reports using SHAP.

🔑 Key Concepts
Shared Responsibility
AWS secures the infrastructure; YOU secure your data, IAM policies, encryption choices, and application configuration. Applies to all AI services.
Bedrock Privacy
AWS guarantees that prompts and responses sent to Bedrock are NOT used to train foundation models. Your data stays yours.
CloudTrail for AI
Records all API calls to Bedrock, SageMaker, and other AI services. Use it for security audits, compliance, and investigating unauthorized access.
SageMaker Lineage
Tracks the entire lifecycle of a model: data sources → processing → training → evaluation → deployment. Critical for reproducibility and compliance.
HIPAA & AI
Healthcare AI workloads must protect PHI (Protected Health Information). Use HIPAA-eligible AWS services, BAA agreements, and encryption everywhere.
Amazon Macie
Automatically discovers and protects sensitive data (PII, PHI, financial data) in S3 using ML. Useful before training ML models on customer data.
